# Crimson Tasks

Цель проекта — дать пользователю список задач с постоянным хранением, фильтрами и счётчиками. Основной сценарий работает без перезагрузки страницы. Визуальная основа — [исходный макет](docs/design/crimson-tasks.png).

## Решения

- `app/main.py` собирает приложение и управляет запуском БД, `app/routes.py` содержит HTTP-эндпоинты и зависимость сессии, `app/schemas.py` — Pydantic-схемы запросов и ответов. После переноса прошли все 35 тестов pytest.
- FastAPI отдаёт страницу Jinja2, статические файлы и JSON API с одного адреса.
- SQLAlchemy хранит задачу с UTC-метками создания, дедлайна и завершения и важностью 0–100. Каждая операция записи завершает транзакцию до ответа.
- JavaScript загружает список целиком и вычисляет фильтры и счётчики из одного массива. Редактирование названия, дедлайна, важности и смена статуса используют частичное обновление `PATCH`.
- Публикация выполняется по отдельной команде. Для проверки достаточно локального запуска.

## Результаты проверок

Анонимные владельцы. Добавлены серверные сессии с хешированными токенами, сроком 30 дней и cookie HttpOnly/SameSite=Lax/Secure для HTTPS. Все CRUD-запросы ограничены владельцем. Миграция сохраняет старые записи без владельца и скрывает их от API. Прошли 42 теста pytest и 12 тестов JavaScript. Два независимых контекста Chrome создали собственные задачи через интерфейс, увидели только свои списки и получили 404 при GET/PATCH/DELETE чужих задач. Проверены повторное открытие с сохранённой сессией, отсутствие и подмена cookie, истечение cookie в браузере и серверного срока. HTTP и HTTPS атрибуты cookie проверены интеграционными тестами.

Категория «Невыполненные» вычисляется в общем frontend-правиле классификации и используется фильтрами, счётчиками и срочностью. Изменения модели и миграции для неё не требуются. Прошли 35 тестов pytest и 12 тестов JavaScript. Chrome подтвердил переход по времени без перезагрузки, обе стороны переключения выполнения с проверкой `completed_at`, возврат в активные после переноса срока, счётчики, фильтры и восстановление списка после обновления. Обе темы проверены на ширинах 1440, 769 и 375 px.

Расширение дедлайнами и важностью выполнено последовательно. Сначала добавлены UTC-поля и транзакционная миграция старой SQLite-схемы с сохранением записей. Затем расширены POST/PATCH и проверена совместимость CRUD. После этого подключены модальные окна, ползунки важности, метаданные карточек и периодический пересчёт срочности. Проверки API и миграции проходят в 35 тестах pytest. Расчёт срочности и границы уровней важности проходят в 10 тестах Node.js. Chrome подтвердил создание и редактирование, локальные поля дат, клавиатурное управление ползунком, сохранение после обновления страницы, движение времени без перезагрузки, выполнение и мобильную раскладку.

Миграция также применена к локальной базе. До и после обновления в ней 0 записей. Сохранность непустой старой базы и повторный запуск миграции проверены отдельным интеграционным тестом. В Chrome дополнительно проверены создание без дедлайна и защита от двух одновременных отправок формы. Новые runtime-зависимости не добавлялись.

Кастомный календарь. Общий компонент Vanilla JavaScript заменяет нативные date/time picker в обоих окнах. В Chrome проверены сетка с понедельника, переключение декабря и января, февраль 2028 с 29 днями, выбор дня и времени с клавиатуры, быстрые сроки, предпросмотр, создание, редактирование и восстановление после обновления страницы. Просроченный исходный дедлайн сохраняется при правке названия, изменённое прошлое время отклоняется. Снимки компонента проверены в обеих темах на ширине 375 px, переполнение также проверено на 768 и 1440 px. Backend, схема БД и алгоритмы срочности и важности в этом расширении сохранены.

- Каркас. `uv sync --locked` прошёл, запрос `GET /` вернул `200` и заголовок Crimson Tasks. `git check-ignore` подтвердил правила для окружения и базы.
- Хранение и API. `uv run --locked pytest` прошёл все 16 проверок, включая повторный запуск приложения с тем же файлом БД. Тесты используют ASGI-транспорт httpx и явно запускают lifespan приложения.
- Интерфейс. Chrome подтвердил создание, оба перехода статуса, фильтры, счётчики, отмену и подтверждение удаления, ввод с клавиатуры и восстановление списка после сетевой ошибки. Снимки с пятью задачами сверены с макетом на 1672 × 941 и проверены на ширине 390 px. На 320–1672 px в семи контрольных точках горизонтальной прокрутки нет. После корректировки мобильной раскладки и стилей повторно прошли 16 тестов API и `node --check`.
- Приёмка. В чистом окружении Python 3.12.14 прошли синхронизация из lock-файла, все 16 тестов и установка без dev-зависимостей. На Python 3.14.0 также прошли все 16 тестов. Отдельная HTTP-проверка Uvicorn подтвердила загрузку страницы и статики, а также сохранность задачи и статуса после перезапуска процесса. Pydantic и AnyIO объявлены явно, поскольку приложение использует схемы Pydantic, а тесты — плагин pytest от AnyIO. Состав lock-файла не изменился.
- Обновление карточек. Прошёл 21 тест API. В Chrome проверены смена статуса только через чекбокс, сохранение нового названия после обновления страницы, валидация, возврат фокуса и удаление только после подтверждения. Диалог удаления проверен на ширине 320 px.
