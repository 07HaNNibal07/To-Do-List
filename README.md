# Crimson Tasks

Одностраничный список задач на FastAPI, SQLite и Vanilla JavaScript. Задачи можно добавлять, переименовывать, отмечать выполненными и удалять. Чекбокс меняет статус в обе стороны, карандаш открывает редактирование, а корзина запрашивает подтверждение. Фильтры и счётчики обновляются без перезагрузки. Данные сохраняются после закрытия страницы и перезапуска сервера.

«Добавить» или Enter открывает окно создания с названием, календарём дедлайна и ползунком важности. Календарь начинается с понедельника, позволяет переключать месяцы и выбирать часы и минуты с клавиатуры. Предпросмотр показывает местные дату и время. Доступны быстрые варианты «Через час», «Завтра» и «Через неделю». Последние два сохраняют местное время текущего момента и сдвигают календарную дату. Прошедшие дни недоступны, время проверяется перед отправкой.

Без выбранной даты задача создаётся без срока. В окне редактирования можно менять название, срок и важность. Кнопка «Без срока» снимает дедлайн после сохранения. Просроченный сохранённый дедлайн разрешено оставить при правке других полей. Изменённый срок должен быть в будущем.

Важность задаётся пользователем от 0 до 100, значение по умолчанию — 50. Ползунок меняет значение с шагом 5 и поддерживает клавиатуру. Уровни важности — низкая 0–24, средняя 25–50, высокая 51–79 и критическая 80–100. Срочность рассчитывается отдельно по времени и обновляется раз в минуту и при возвращении на вкладку.

Категории взаимоисключающие. Активные задачи ещё не выполнены и имеют будущий дедлайн либо не имеют срока. «Невыполненные» содержит незавершённые задачи с истёкшим дедлайном. Отмеченные галочкой задачи относятся к выполненным независимо от срока. «Все задачи» объединяет три категории. Счётчики и фильтры пересчитываются при действиях и минутном обновлении. Перенос дедлайна на будущее возвращает невыполненную задачу в активные.

Интерфейс адаптируется к мобильному экрану и работает с клавиатуры. Исходный макет и результаты приёмки доступны в репозитории. [Визуальный макет](docs/design/crimson-tasks.png) · [План разработки](PLAN.md)

Каждый браузер автоматически получает отдельную анонимную сессию. Cookie `crimson_session` действует 30 дней, имеет `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS. Сервер хранит SHA-256-хеш случайного 256-битного токена и срок действия. Список, создание, чтение отдельной задачи, редактирование и удаление ограничены текущим владельцем. Чужой идентификатор возвращает `404`.

При повторном открытии с действующей cookie прежние задачи доступны. После удаления, подмены или истечения cookie создаётся новая пустая сессия. Восстановление доступа к прежней сессии без её cookie не предусмотрено. Перенос на другое устройство требует сохранённой сессии, а знание токена даёт доступ к её задачам.

## Установка и запуск

Нужны Python 3.12 или новее и `uv`. Выполните из корня проекта.

```sh
uv sync --locked
uv run --locked uvicorn app.main:app --reload
```

Откройте [Crimson Tasks](http://127.0.0.1:8000). Список при первом запуске пуст. Приложение создаёт `data/tasks.sqlite3` при старте. Чтобы использовать другую базу, задайте переменную окружения `CRIMSON_DB_PATH` с абсолютным путём к файлу.

## Проверка

```sh
uv run --locked pytest
node --test tests/task-timing.test.cjs
```

Интеграционные тесты используют временные SQLite-файлы. Они проверяют HTTP-операции, валидацию, миграцию старой схемы, UTC, важность, время завершения и сохранение данных после повторного запуска. Node.js нужен для тестов frontend-расчётов и использует встроенный тестовый раннер. Для проверки интерфейса создайте задачу через Enter, переключите её статус в обе стороны, проверьте счётчики во всех фильтрах, обновите страницу и удалите задачу.

## API

| Метод и путь | Действие |
| --- | --- |
| `GET /api/tasks` | Получить задачи текущего владельца. |
| `GET /api/tasks/{task_id}` | Получить свою задачу или `404`. |
| `POST /api/tasks` | Создать активную задачу. Обязателен `title`, доступны `due_at` и `importance`. |
| `PATCH /api/tasks/{task_id}` | Изменить `title`, `due_at`, `importance` или булево `is_completed`. Пропущенные поля сохраняют своё значение. `due_at: null` снимает дедлайн. |
| `DELETE /api/tasks/{task_id}` | Удалить задачу. Успешный ответ имеет статус `204`. |

Название содержит от 1 до 200 символов после удаления пробелов по краям. Интерактивное описание доступно в [Swagger UI](http://127.0.0.1:8000/docs).

Даты API содержат часовой пояс, сохраняются в UTC и возвращаются с `Z`. Дедлайн без часового пояса отклоняется. `created_at` устанавливает сервер, `completed_at` фиксируется только при переходе в выполненное состояние и сбрасывается при возврате в активное. В браузере даты показаны в локальном часовом поясе.

При старте схема SQLite автоматически расширяется в транзакции с блокировкой записи. Существующие задачи сохраняют идентификаторы, названия и статусы. Их неизвестное время создания заполняется единым временем миграции. Дедлайн и неизвестное время завершения остаются пустыми, важность получает 50. Перед обновлением сервера сохраните резервную копию файла БД. Старые версии приложения следует остановить перед запуском обновлённой.

Миграция анонимных сессий добавляет таблицу `anonymous_sessions` с хешем и сроком действия, поле `tasks.owner_id` и индекс по владельцу. Старые задачи получают `owner_id = NULL` и сохраняются в БД, но недоступны посетителям через API. Автоматического присвоения общих старых задач первому посетителю нет. Просроченные сессии и их задачи остаются в БД, доступ по истёкшему токену прекращается.

Прогресс показывает долю израсходованного времени от создания до дедлайна. Статусы проверяются по приоритету — выполнено, просрочено, осталось не более трёх часов, прошло не менее 80%, не менее 50%, времени достаточно. Значение полосы ограничено 0–100%. У выполненных задач оно фиксируется на момент завершения. Для старых выполненных задач с неизвестным временем завершения полоса скрыта. Расчёт в интерфейсе использует часы устройства.

## Публикация демо

На сервере или хостинге с поддержкой Python выделите постоянный диск и задайте `CRIMSON_DB_PATH` внутри него. Настройте HTTPS и автоматический перезапуск процесса. Для демо достаточно одного экземпляра приложения.

```sh
uv sync --locked --no-dev
uv run --locked --no-dev uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Укажите порт, который выделяет хостинг. За reverse proxy настройте доверенные адреса прокси Uvicorn через `--forwarded-allow-ips`, чтобы приложение корректно определяло HTTPS и устанавливало `Secure` cookie. После развёртывания создайте пробную задачу и проверьте её наличие после перезапуска с той же cookie. Откройте второй независимый браузерный профиль и убедитесь, что его список пуст. HTML и ответы API имеют `Cache-Control: private, no-store`.

## Развёрнутый VPS

Публичный адрес — [Crimson Tasks](https://48.103.117.162/).

- Код расположен в `/opt/crimson-tasks`, исходный коммит — `f9972ef666d2d5b69aa60b4ed8db8706fc7978eb`.
- SQLite находится в `/var/lib/crimson-tasks/tasks.sqlite3`, права каталога — `0700`, файла — `0600`, владелец — `crimson`.
- `crimson-tasks.service` запускает Uvicorn от пользователя `crimson` на `127.0.0.1:8000`.
- `caddy.service` запускает Caddy 2.11.9 от пользователя `caddy`, принимает TCP 80/443 и обновляет IP-сертификат Let’s Encrypt с профилем `shortlived`.
- Конфигурация прокси находится в `/etc/caddy/Caddyfile`, сертификаты — в `/var/lib/caddy/data`.
- Обе службы включены в автозапуск. VPN-контейнер `amnezia-awg2` использует UDP 37034. Его время запуска и счётчик перезапусков сохранены при развёртывании.

На VPS отсутствует авторизация в приватном GitHub-репозитории. Для обновления получите изменения на своём компьютере и передайте Git bundle. В PowerShell из каталога проекта выполните команды ниже. Ключ деплоя хранится в локальном `~/.ssh`, его приватная часть остаётся на компьютере.

```powershell
git pull --ff-only origin main
git bundle create "$env:TEMP\crimson-tasks-update.bundle" main
scp -i "$env:USERPROFILE\.ssh\crimson_tasks_vps_ed25519" "$env:TEMP\crimson-tasks-update.bundle" root@48.103.117.162:/opt/crimson-tasks-update.bundle
ssh -i "$env:USERPROFILE\.ssh\crimson_tasks_vps_ed25519" root@48.103.117.162
```

В SSH-сессии сначала создайте согласованную резервную копию SQLite.

```bash
umask 077
python3 - <<'PY'
import sqlite3
from datetime import datetime, timezone
from pathlib import Path

folder = Path('/var/lib/crimson-tasks')
stamp = datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%S%fZ')
source = sqlite3.connect(folder / 'tasks.sqlite3')
backup = sqlite3.connect(folder / f'backup-{stamp}.sqlite3')
try:
    source.backup(backup)
finally:
    backup.close()
    source.close()
PY
```

Затем обновите код и перезапустите службу приложения. Выполняйте следующую команду только при успешном завершении предыдущей.

```bash
cd /opt/crimson-tasks
git fetch /opt/crimson-tasks-update.bundle main
git merge --ff-only FETCH_HEAD
UV_CACHE_DIR=/var/cache/crimson-tasks uv sync --locked --no-dev
systemctl restart crimson-tasks
systemctl is-active crimson-tasks caddy
curl --fail --silent --show-error --output /dev/null https://48.103.117.162/
```

Логи приложения доступны через `journalctl -u crimson-tasks -n 50 --no-pager`, прокси — через `journalctl -u caddy -n 50 --no-pager`. Миграции выполняются приложением при старте, а SQLite остаётся вне Git-репозитория.
